    Nomograms.Nomograms

    source 
    Nomograms

    Build, solve and render nomograms (alignment charts).

    A nomogram is a chart that computes by alignment: lay a straightedge across the scales at the values you know, and read the answer where it crosses the remaining scale. The scales are drawn so that any straight line crossing them picks out a solution of an equation. The geometry rests entirely on d'Ocagne's collinearity criterion,

    | x1  y1  1 |
| x2  y2  1 | = 0
| x3  y3  1 |

    This package therefore represents every scale as a parametric curve value -> (x, y), and does all its arithmetic by finding where a line crosses a curve. The same solver handles forward and inverse problems, and layouts other than the built-in parallel-axis construction need no extra code.

    Getting started

    using Nomograms

nom = additive_nomogram(
    Variable(:R1, ReciprocalScale(); domain = (1, 10), label = "R1 (ohm)"),
    Variable(:R2, ReciprocalScale(); domain = (1, 10), label = "R2 (ohm)"),
    Variable(:R, ReciprocalScale(); label = "R (ohm)");
    title = "Resistors in parallel",
)

evaluate(nom; R1 = 4, R2 = 6)          # -> (R1 = 4.0, R2 = 6.0, R = 2.4)
save_svg("parallel.svg", nom; isopleths = [isopleth(nom; R1 = 4, R2 = 6)])

    See additive_nomogram, multiplicative_nomogram, evaluate, isopleth, svg and nomogramplot.

    Nomograms.DEFAULT_ISOPLETH_COLORS

    source 
    DEFAULT_ISOPLETH_COLORS

    Blue, orange and aqua, in that order. All the isopleths on a chart are visible at once, so every pair of colours has to stay distinguishable under colour-vision deficiency, and no fourth hue does once every pair is taken into account. The colours were checked with a validator: the worst pair is ΔE 9.2 under deuteranopia and 24.0 in normal vision, against a target of at least 8.

    d3's category10 palette is not used because its orange and green are only ΔE 0.7 apart under protanopia, which makes them look the same.

    Nomograms.DEFAULT_ISOPLETH_DASHES

    source 
    DEFAULT_ISOPLETH_DASHES

    Dash patterns, cycled one step behind the colours, so a fourth isopleth is dashed blue instead of a second plain blue. Lines are never told apart by colour alone, so a chart can carry more lines than there are safe colours.

    Nomograms.AbstractNomogram

    source 
    AbstractNomogram

    A chart made of Scales on a canvas. Drawing one (ticks, labels, bounding box and both backends) needs only the scales, the canvas and the title, so that code is written against this type. Subtypes differ in how they are solved: a Nomogram is one alignment line through every scale, while a CompoundNomogram is several stages read in turn.

    Nomograms.CompoundNomogram

    source 
    CompoundNomogram

    Several Nomogram stages sharing variables, for relations that need more than three variables.

    A single alignment line relates at most three scales, so a four-variable relation is split into two, g(a, b) = t and h(t, c) = d, which share the intermediate t. The reader lays a line across the first stage to find where it crosses the shared scale, then pivots about that point and reads the second stage. This is why the shared scale is often called the pivot or pivot line.

    Build one with compound, which positions the stages so their shared scales coincide. Drawing works exactly as for a single nomogram; solving propagates values from stage to stage (see evaluate).

    Nomograms.ContourChart

    source 
    ContourChart

    A chart read at a point: two axis variables span a rectangle, and every other variable is drawn as a family of curves of constant value across it. Any two values fix the point where their curves cross, and every other value is read there. Variables on rings around the chart are read along a line from its centre through the point.

    Build one with contour_chart. Solve it with evaluate and evaluate_all, given any two of its variables, and mark a point on it with crossing.

    Nomograms.Crossing

    A point on a ContourChart where curves cross: every variable's value there, and where it is on the page. Build one with crossing and draw it with drawing(chart; crossings = [...]).

    Nomograms.Grid

    source 
    Grid(u::Variable, v::Variable, surface)

    A two-parameter family of points, surface(u, v) -> (x, y), drawn as a mesh of curves. It takes the place of one of the three scales an alignment line crosses.

    Three collinear points relate three variables. A grid carries two variables in a single point, so a chart with a grid and two ordinary scales relates four. This is a different construction from compound, which chains stages through a shared pivot. A grid can handle relations that a chain cannot: a pivot works only when the first two variables combine into one intermediate, while a grid handles a true two-parameter family.

    Deriving a grid

    With scale a on x = 0 at height f(a) and scale b on x = 1 at height g(b), a line between them meets x = x₃ at (1-x₃)·f(a) + x₃·g(b). So the line passes through a grid point (x₃, y₃) exactly when

    α·f(a) + β·g(b) = γ        with   x₃ = β/(α+β),  y₃ = γ/(α+β)

    So any relation that can be written this way, with the coefficients α, β, γ depending on the two grid variables, has a grid. The mesh is truly two-dimensional as long as (α : β : γ) sweeps out a region. If it sweeps out only a curve, the grid collapses to a line, and the relation needed compound instead.

    See grid_nomogram.

    Nomograms.GridNomogram

    Nomograms.NomogramStyle

    source 
    NomogramStyle(; kwargs...)

    Sizes and thresholds for turning a Nomogram into geometry. All lengths are in chart units, the same units as a nomogram's width and height (70 by 100 by default), so one style works unchanged at any output size and in either backend.

    The defaults follow the proportions of a standard d3 axis: hairline rules, short ticks and small type. At the default pxperunit = 4 a chart unit is 4 pixels, which gives roughly 1px strokes, 6px major ticks, 3px of label padding and 10px labels.

    Keywords

    • majorticklength, minorticklength: tick mark lengths.

    • graded_ticks: whether ticks between those lengths are graded by importance, as on a ruler: wholes longest, then halves, quarters and so on on a fraction axis; 10s, 5s, then the rest on an integer one; decades, whole digits, then tenths on a logarithmic one. Labels sit the same distance from the axis whatever their tick's length. false gives every labelled tick the major length and every other tick the minor length.

    • ticklabelgap: gap between a tick's outer end and its label.

    • ticklabelsize, titlesize: text heights.

    • titlegap: gap between the end of an axis and its title.

    • min_major_spacing, min_minor_spacing: a tick is dropped if it would land closer than this to one already placed. This keeps a non-uniform axis readable.

    • label_minors: whether minor ticks get labels too.

    • endpoint_ticks: whether to add the ends of each domain as labelled ticks when they fit. An end that needs more than three significant figures is not labelled, since it is a derived limit such as 237.4 and not a value anyone chose.

    • ticklabelrotation: :horizontal leaves tick labels upright; :tangent turns each to run along its scale, which reads better on a steep or curved axis.

    • resolve_collisions: whether to drop tick labels that would overlap a label from another scale, and nudge isopleth labels clear of both.

    • avoid_isopleths: whether to also drop a tick label that an alignment line crosses. Such a label is hard to read, and the tick mark still shows where the value falls.

    • collisionpad: extra clearance required between two labels.

    • axislinewidth, gridlinewidth, tickwidth, isoplethwidth: stroke widths. The grid width applies to the strands of a Grid. Its strands are read like any other scale, so by default they match the axes; make it thinner, or pass gridcolor to svg or nomogramplot, for a lighter grid.

    • isopleth_overhang: how far an alignment line extends past the outermost scale.

    • markersize: radius of the dot where an isopleth meets a scale.

    • min_curve_spacing: on a ContourChart, a curve is drawn only where it is at least this far from its neighbours, judged against the curves at least as round as it is. A crowded family thins out locally, as on a Smith chart, rather than everywhere.

    Nomograms.ScaleTransform

    source 
    ScaleTransform

    A strictly monotone map from a variable's own units onto the functional axis of a nomogram, together with its inverse.

    A three-variable alignment chart exists whenever the relation can be written in the separable form f1(u) + f2(v) = f3(w); a ScaleTransform is one of those fs. Because the inverse comes with the forward map, the construction can compute the third variable's domain exactly instead of searching for it.

    Implement transform for a new subtype, and either invtransform or hasinverse(::T) = false (in which case inversion falls back to bracketed root finding over the variable's domain).

    Nomograms.TabulatedScale

    source 
    TabulatedScale

    A ScaleTransform known only numerically: values and derivatives at a set of nodes, joined by cubic Hermite interpolation.

    auto_nomogram builds these when it derives a transform by integration, because most of those integrals have no useful closed form. With exact derivatives at the nodes, the interpolation error is fourth order in the node spacing, far smaller than anything a chart can show. Outside the tabulated range it extrapolates linearly, so a solver probing an ulp past the edge of a domain gets an answer instead of an exception.

    Nomograms.Variable

    source 
    Variable(name, transform = LinearScale(); kwargs...)

    One variable of a nomogram, before it has been placed on the page.

    Arguments

    • name::Symbol: the keyword used to refer to this variable in evaluate and isopleth.

    • transform::ScaleTransform: the f that this variable contributes to the separable relation f1(u) + f2(v) = f3(w).

    Keywords

    • domain: (lo, hi) in the variable's own units. May be nothing for the result variable of a construction, whose range is then derived from the other two. With Unitful loaded the ends may be quantities, (1u"ft", 10u"ft"), which also sets unit.

    • unit: the unit the axis is drawn in, such as u"ft" (needs Unitful). Values passed to evaluate and isopleth may then be quantities in any unit of the same dimension, results come back as quantities, and a plain number is read as being in this unit. Defaults to the unit of the domain's ends, if they have one.

    • label: axis title; defaults to string(name). The unit is drawn after it, length (ft), unless unitlabel = false.

    • ticks, minorticks: explicit tick values, bypassing automatic selection.

    • tickformat: value -> String. Defaults to fractionformat for tickstyle = :fraction and to plain numbers otherwise.

    • tickstyle: how automatic tick values are picked.

      • :linear or :log for round decimals spaced evenly or by decade;

      • :integer for whole numbers only, for a count such as gear teeth or turns;

      • :fraction for fractions whose denominator divides maxden (halves, quarters, eighths and sixteenths by default), labelled as fractions, such as 1 3/8 instead of 1.375;

      • :auto to take it from the transform. A construction may override :auto: for example, an N-chart's ratio axis gets logarithmic ticks when it spans a decade or more.

      Whichever is chosen, ticks are thinned by distance on the page, roundest first.

    • maxden = 16: for tickstyle = :fraction, the finest fraction offered; every denominator dividing it is used. 16 gives halves to sixteenths, 12 gives halves, thirds, quarters, sixths and twelfths.

    A domain written with Rational ends, such as (1//10, 1//1), makes a variable left on tickstyle = :auto a :fraction one, with maxden the least common multiple of the ends' denominators (10 here), or 16 if they are all whole numbers. An explicit tickstyle or maxden takes precedence, and a floating-point end turns this off.

    • side: :left, :right, or :auto (the construction chooses).

    • titleend: which end of the scale the title goes past: :start or :stop for the low or high end of the domain, or :auto for whichever end is higher on the page. Set this when the automatic choice puts the title somewhere crowded, as happens for the strands of a Grid that converge at one end.

    Nomograms.additive_nomogram — Tuple{Variable, Variable, Variable}

    source 
    additive_nomogram(v1, v2, v3; width = 70, height = 100, title = "", max_modulus_ratio = 4)

    A parallel-scale nomogram for the separable relation

    f1(v1) + f2(v2) = f3(v3)

    where each fi is the ScaleTransform carried by the corresponding Variable. v3 is the result variable and is drawn as the middle axis; it may leave domain = nothing, in which case its range is derived from the other two.

    The construction

    Place v1 on x = 0 at y1 = a1 * (f1 - p0) and v2 on x = W at y2 = a2 * (f2 - q0), where [p0, p1] and [q0, q1] are the ranges of f1 and f2 over their domains and a1 = H/(p1-p0), a2 = H/(q1-q0) fit each to the canvas height H.

    A straight line through those two points crosses x = L*W at

    y = (1-L) * y1 + L * y2

    Choosing L = a1 / (a1 + a2) makes (1-L)*a1 == L*a2 == a1*a2/(a1+a2) =: a3, so that

    y = a3 * (f1 + f2) - a3 * (p0 + q0)

    which is exactly a linear scale for f3 = f1 + f2 with gradient a3. Reading a value off the middle axis therefore solves the relation. Because a3 * (1/a1 + 1/a2) == 1, the middle axis spans the same [0, H] as the outer two: its height and position are determined by the outer scales and are not free parameters.

    Keeping the middle axis clear

    The middle axis sits at L = a1 / (a1 + a2) of the way across, so it lies close to whichever outer axis has the smaller gradient, which is the one whose f spans more. Over [1, 1000] against [11, 14] on logarithmic scales the gradients differ about 28-fold, and the middle axis lands 3% of the way across, nearly on top of its neighbour. So the steeper gradient is capped at max_modulus_ratio times the other, by shortening that axis and centring it vertically. An outer axis shifted by d shifts the line's crossing of the middle one by d times that axis's share, L or 1 - L, so the middle axis is shifted to match and every reading is unchanged. The middle axis then lies at least 1/(1 + max_modulus_ratio) of the width from either outer axis: a fifth, by default. The shortened axis only loses resolution it could spare, since it was the one stretched furthest. Pass max_modulus_ratio = Inf for full-height outer axes whatever their ranges.

    Example

    julia> nom = additive_nomogram(
           Variable(:a; domain = (0, 10)),
           Variable(:b; domain = (0, 20)),
           Variable(:total),
       );

julia> nom[:total].domain
(0.0, 30.0)

julia> round(evaluate(nom; a = 3, b = 4).total; digits = 10)
7.0

    Nomograms.align_residual — Tuple{Scale, Any, Tuple{Float64, Float64}, Tuple{Float64, Float64}}

    source 
    align_residual(s::Scale, value, p, q) -> Float64

    Signed area (twice the triangle area) of p, q and point(s, value). Zero exactly when the three are collinear, so this is the residual whose root evaluate seeks.

    This is d'Ocagne's determinant criterion written as a cross product. Every layout in this package is a choice of scale curves that makes this criterion agree with the relation being charted.

    Nomograms.auto_nomogram — Tuple{Any, Vararg{Any}}

    source 
    auto_nomogram(F, x, y, [z]; kwargs...) -> Nomogram
auto_nomogram(F, x, y, w, ..., z; kwargs...) -> CompoundNomogram

    Build a nomogram for z = F(x, y), or for z = F(x, y, w, …) with any number of inputs, from the function as you would normally write it.

    The other constructors need you to rewrite your formula first, as f₁(u) + f₂(v) = f₃(w) with the transforms chosen and their inverses supplied. auto_nomogram does that for you:

    nom = auto_nomogram((r, n) -> (1 + r/100)^n, :r => (1, 20), :n => (1, 30), :growth)

    Give each input as a Variable with a domain, or as name => (lo, hi), in the order F takes them. The last argument names the result, as a Variable or a name. The exception is when there are exactly two arguments after F: both are then inputs, and the result is called :z. The result's domain is derived from F; if you give one, it is checked. Labels, tick formats and explicit ticks on the variables are used as given. Transforms are always derived, and replace any you set.

    How

    F can be drawn on three straight parallel scales exactly when transforms exist with h(z) = f(x) + g(y). Differentiating shows that requires

    F_x / F_y = f′(x) / g′(y)

    so the test is whether ln|F_x / F_y| splits into a part in x plus a part in y (see separability_defect). When it does, the same identity gives f′ and g′. Integrating them gives f and g, and h is found by walking across the level sets of F. The transforms come out as TabulatedScales, and each axis gets linear or decade-based ticks according to how its transform spreads its values.

    Verification

    The finished chart is then solved over a grid of inputs, and every answer is compared with F itself. If any answer differs by more than rtol times the result's range, no chart is returned: the call throws an error that reports the disagreement it measured. The chart's relation is F, so relation_residual and max_relation_residual check against your formula, not a derived one.

    More than two inputs

    One alignment line relates three scales, so F(x, y, w) is drawn as a chain of compound stages and the result is a CompoundNomogram. That needs F to depend on some pair of its inputs only through a single combination of them, t = T(x, y), which holds exactly when F_x / F_y does not depend on w. The first stage then charts t, the second charts z from t and w, and the reader pivots between them on an unmarked pivot line. More inputs are reduced in the same way, one pair at a time.

    Every pairing is tried. A pairing can fail for two reasons. F may not depend on the pair through a single combination at all. Or it may, but the two stages need the intermediate on different scales. The standard example is (x + y)·w, where the first stage needs a linear scale and the second a logarithmic one. That case needs a grid, which you have to derive by hand (grid_nomogram). If no pairing works, the error lists what went wrong with each.

    One curved scale

    A two-input formula that is not separable may still have a chart on two straight scales and one curve, such as the chart for the roots of a quadratic. Each variable is tried on the curve in turn. With G(u, v, w) = 0 and w on the curve, such a chart exists exactly when ln|G_u / G_v| splits as φ(w) + a(u) − b(v). This is tested by a least-squares fit along level sets of w. The derivatives it needs come from automatic differentiation of F itself, so F must accept generic number types as well as Float64. The first curved chart from a given function takes a few seconds to compile.

    Formulas with no chart

    A formula with neither kind of chart is refused, and the error gives the reason for each arrangement tried. The formula may still have a chart with more curved scales or a grid, but you have to derive the form by hand: see determinant_nomogram and grid_nomogram. A formula that is not monotone in a variable over its domain is also refused, because a straight scale cannot fold back on itself.

    Any formula of two inputs can still be drawn as curves of constant value, read where they cross: see contour_chart.

    Keywords

    • width, height, title: as for the other constructions. width defaults to 70 for two inputs. In a chain it is the width of the last stage, and the default grows with the chain, 35 per input after the first. An earlier stage always has one input inside the rest of the chain, so it is mirrored and resized, to between a quarter of width and width, to put that input midway between the axes already there. Every way of pairing the inputs is tried for the first two levels of the chain, and the one whose axes end up furthest apart is kept.

    • rtol = 1e-6: the largest disagreement with F to accept, relative to the result's range.

    Nomograms.compound — Tuple{Vararg{Nomogram}}

    source 
    compound(stages::Nomogram...; title = "", atol = 1e-6) -> CompoundNomogram

    Join nomogram stages into one chart, positioning each so that the scales it shares with an earlier stage lie exactly on top of them.

    Variables are shared by name. Each stage after the first must share at least one variable with a stage already placed, and that shared scale must have the same values over the same domain in both stages. So build the later stage with the domain that the earlier one derived:

    first = additive_nomogram(a, b, Variable(:t))          # :t derived
second = additive_nomogram(Variable(:t; domain = first[:t].domain), c, d)
chart = compound(first, second)

    The stages are aligned by a similarity (rotation, uniform scaling and translation) chosen to carry the later stage's shared scale onto the one already placed. The match is then checked along the whole domain, not only at the two points used to compute it. A similarity is affine, so it cannot change what any stage computes.

    The shared scale is drawn once. The stages usually overlap instead of sitting side by side. A parallel-axis construction puts its result between its two inputs, so when two such stages share a pivot, the other scales of both stages lie on either side of it. Use project to reshape the result if the layout is awkward.

    Nomograms.concurrent_nomogram — Tuple{Variable, Variable, Variable}

    source 
    concurrent_nomogram(v1, v2, v3; width = 100, height = 50, title = "")

    A concurrent-scale nomogram for the relation

    1/f1(v1) + 1/f2(v2) = 1/f3(v3)

    which covers resistors in parallel, capacitors in series and the thin-lens equation. Its three scales start from one point, the zero of every scale: v1 and v2 fan out towards the top corners, and v3 runs up the middle between them. v3 may leave domain = nothing, in which case the range it can reach is derived from the other two. All three transforms must be zero or more over their domains.

    The construction

    Put the common zero at (W/2, 0), v1 at (W/2 - c·f1, d·f1), v2 at (W/2 + c·f2, d·f2) and v3 at (W/2, 2d·f3). A line through the first two crosses x = W/2 at height 2d·f1·f2 / (f1 + f2), which is 2d·f3 exactly when the relation holds. c and d are chosen so that the longer outer scale ends at a top corner.

    Doerfler derives the same chart with the outer scales at an angle A either side of the middle one and scale factors m1 = m2 = m3 / (2 cos A) (see the Bibliography). Stretching a chart to fill its canvas cannot change what it computes, and it absorbs the angle, so here width and height set the spread instead.

    Example

    julia> nom = concurrent_nomogram(
           Variable(:R1; domain = (0, 1000)),
           Variable(:R2; domain = (0, 1000)),
           Variable(:R),
       );

julia> round(evaluate(nom; R1 = 400, R2 = 600).R; digits = 10)
240.0

    Nomograms.contour_chart — Tuple{Union{Variable, Pair{Symbol, <:Tuple}}, Union{Variable, Pair{Symbol, <:Tuple}}, Vararg{Pair}}

    source 
    contour_chart(x, y, fields...; kwargs...) -> ContourChart
contour_chart(F, x, y, [z]; kwargs...) -> ContourChart

    A chart read at a point. x runs along the bottom and y up the left side, each a Variable with a domain or simply name => (lo, hi). Every other variable is a field, given as variable => (x, y) -> value, and is drawn as its curves of constant value. Read the chart by finding where the curves of any two known values cross; every other value is read at that point.

    moody = contour_chart(
    Variable(:Re, LogScale(); domain = (4e3, 1e8), label = "Reynolds number"),
    Variable(:f, LogScale(); domain = (0.008, 0.1), label = "friction factor"),
    Variable(:roughness; domain = (1e-6, 0.05), label = "ε/D") =>
        (Re, f) -> 3.7 * (10^(-1 / (2sqrt(f))) - 2.51 / (Re * sqrt(f))),
)
evaluate(moody; Re = 1e5, roughness = 1e-4).f

    A field only needs some formula for its value at each point. The Colebrook equation cannot be solved for the friction factor, but it can be solved for the roughness, so the chart above is the Moody diagram.

    The second form charts a formula z = F(x, y) and works for any F. When F passes the test auto_nomogram applies, the axes take the transforms it recovers, and every curve of z comes out a straight line, all of them parallel; otherwise the axes keep the variables' own transforms.

    Field functions, like transforms, take and return plain numbers, in each variable's unit if it has one. The formula form calls F with quantities when the axes have units, as auto_nomogram does.

    Curves

    A field gets curves at round values over the range it takes on the chart, or over its domain if it declares one, chosen as its ticks or tickstyle say. A field left on tickstyle = :auto gets logarithmic values when its range is positive and spans two decades or more. Each curve is drawn only where it stands at least min_curve_spacing (see NomogramStyle) from its neighbours on the page, judged against the curves at least as round as it is, so a crowded family thins out locally rather than everywhere. The roundest curves are labelled where they leave the chart, when there is room.

    Charts on another grid

    With axes = false the two axis variables are coordinates of a plane rather than scales: nothing is drawn for them, and the plane keeps its proportions, so a circle stays round. The Smith chart is drawn this way, on the plane of the reflection coefficient, with resistance and reactance as fields:

    z(u, v) = (1 + complex(u, v)) / (1 - complex(u, v))
smith = contour_chart(
    :u => (-1, 1),
    :v => (-1, 1),
    Variable(:r; domain = (0, 50), ticks = [0.2, 0.5, 1, 2, 5]) => (u, v) -> real(z(u, v)),
    Variable(:x; domain = (-50, 50), ticks = [-2, -1, 0, 1, 2]) => (u, v) -> imag(z(u, v));
    axes = false,
    region = (u, v) -> u^2 + v^2 <= 1,
    rings = [Variable(:angle; domain = (-180, 180)) => θ -> (1.08cosd(θ), 1.08sind(θ))],
    labelat = (r = :x => 0,),
)

    Keywords

    • width = 100: the width of the chart, in chart units.

    • height: its height; 75 by default, or with axes = false, whatever keeps the plane's proportions.

    • title.

    • region: (x, y) -> Bool, the part of the rectangle the chart covers. Fields have no value outside it, so curves stop at its edge and nothing there can be read: the saturation line of a psychrometric chart, say. Its edge is drawn.

    • grid = true: whether to draw lines across the chart at the axes' tick values.

    • axes = true: whether x and y are drawn as axes, or are only the plane's coordinates.

    • rings: scales around the chart, each variable => value -> (x, y), a curve in the plane's coordinates. A ring is read along a line from centre through the point, and takes part in evaluate like any other variable.

    • centre: the point rings are read from, in the plane's coordinates; the middle of the plane by default.

    • labelat: where to label a family inside the chart, as field = other => value: each curve is labelled where it crosses the curve other = value, set along the curve on a band of background colour. labelat = (r = :x => 0,) labels a Smith chart's resistance circles along its real axis. Other families are labelled where their curves end.

    Nomograms.determinant_nomogram — Tuple{Vararg{Pair}}

    source 
    determinant_nomogram(var => curve, var => curve, var => curve, ...; kwargs...)

    A nomogram from scales given directly as curves, fitted to the canvas for you.

    This is the general constructor. Every three-variable nomogram is a set of parametric curves positioned so that d'Ocagne's determinant

    | x₁(u)  y₁(u)  1 |
| x₂(v)  y₂(v)  1 |  =  0
| x₃(w)  y₃(w)  1 |

    vanishes exactly when the relation holds. additive_nomogram and ratio_nomogram are two particular solutions of that condition. This constructor accepts any other solution you can write down, including curved and concurrent layouts that parallel axes cannot express.

    Each argument is a Variable paired with a function from its value to a point. The curves can use whatever coordinates suit the geometry: their combined bounding box is measured and mapped onto width × height. An affine map keeps collinear points collinear, so the fit cannot change what the chart computes. This includes the default fit, which scales the two axes by different factors to fill the canvas.

    Keywords

    • width, height: the canvas to fit to.

    • preserve_aspect: fit with one scale factor and centre the result, rather than stretching each axis to fill.

    • relation: the algebraic relation, if you have it, for relation_residual and max_relation_residual to check the geometry against. It is optional; the chart draws and solves without it.

    • title, nsamples: chart title, and how finely curves are sampled when measuring the bounding box.

    Every variable must have a domain. There is no designated result variable, so no domain can be derived.

    Example

    The parallel-axis construction, written out by hand in its natural coordinates. Scales at x = 0, 2 and 1, with the middle one at half scale, encode u + v = w; the fit then stretches that 2 × 10 sketch onto the full canvas.

    julia> nom = determinant_nomogram(
           Variable(:u; domain = (0, 10)) => u -> (0.0, u),
           Variable(:v; domain = (0, 10)) => v -> (2.0, v),
           Variable(:w; domain = (0, 20)) => w -> (1.0, w / 2);
           relation = (u, v, w) -> u + v - w,
       );

julia> round(evaluate(nom; u = 3, v = 4).w; digits = 10)
7.0

julia> point(nom[:v], 10)
(70.0, 100.0)

    Nomograms.fan — Tuple{AbstractNomogram}

    source 
    fan(nom; spread = 90, hub = 0.35, radius = 100, inward = :auto) -> nomogram

    Redraw a chart with its axes as spokes radiating from one centre. The fanned chart gives exactly the same answers as the original. The result is the same kind of chart as nom: a Nomogram, a CompoundNomogram or a GridNomogram.

    Parallel lines meet at a point at infinity, and a projective map can bring that point onto the page. Collinear points stay collinear under such a map, so the chart still works (see project). Every vertical axis becomes a spoke through the new point, including the pivot lines of a compound chart and the strands of a grid.

    Straight lines stay straight, so the far ends of the spokes lie on a straight chord, not an arc, and the middle spokes are shorter than the outer ones; the wider the fan, the bigger the difference. At 90° the middle spokes' tips line up level with the outer spokes' tips.

    The map also squeezes everything near the centre. So by default the chart is laid out both ways round, once with the top of each axis at the rim and once with it at the hub, and the layout that keeps more tick labels is used. A scale that is already crowded at one end, such as a reciprocal scale, works best with that end at the rim.

    Keywords

    • spread = 90: the angle in degrees between the outermost spokes; less than 180.

    • hub = 0.35: where the spokes start, as a fraction of their length from the centre.

    • radius = 100: the length of the outer spokes, in chart units.

    • inward = :auto: true puts the top of each axis at the hub, false at the rim.

    • title: defaults to the chart's own.

    fan works on any chart, but it is designed for parallel axes. A diagonal or curved scale is reshaped too and stays correct, but it does not become a spoke.

    Nomograms.project — Tuple{Nomogram, AbstractMatrix}

    source 
    project(nom::Nomogram, H::AbstractMatrix; kwargs...) -> Nomogram
project(nom::Nomogram, src => dst; kwargs...) -> Nomogram

    Reshape a nomogram with a projective map. The reshaped chart gives exactly the same answers as the original.

    A projective map sends straight lines to straight lines, so it preserves the collinearity that a nomogram depends on. Everything else about the picture can change. For example, you can pull open a region where the ticks are crowded together, and the chart still computes exactly what it did before.

    The second form builds the map from four point correspondences with projective_transform, which is usually the easiest way to specify it: give the corners of a quadrilateral in the current chart and where they should end up.

    A projective map can move the bounding box anywhere, so the result is fitted to the canvas again. That fit is affine, and an affine map composed with a projective one is still projective, so the answers are still unchanged.

    Keywords

    • width, height: canvas for the reshaped chart; defaults to the original's.

    • preserve_aspect, nsamples: as for determinant_nomogram.

    • title: defaults to the original's.

    Example

    julia> nom = additive_nomogram(
           Variable(:a; domain = (0, 10)),

    Nomograms.projective_transform — Tuple{Any, Any}

    source 
    projective_transform(src, dst) -> Matrix{Float64}

    The 3×3 homography taking the four points src to the four points dst, each given as a 4-tuple (or vector) of (x, y).

    Four correspondences fix a projective map exactly, so this is a practical way to describe one: you say where four corners should land instead of writing out nine coefficients. No three of the four source points may be collinear, and likewise for the destination points.

    Nomograms.proportional_nomogram — NTuple{4, Variable}

    source 
    proportional_nomogram(v1, v2, v3, v4; width = 70, height = 100, title = "")

    A proportional nomogram for the four-variable relation

    f1(v1) / f2(v2) = f3(v3) / f4(v4)

    such as the ideal gas law written V/T = nR/p, or the law of sines. It is two N charts sharing their diagonal. v1 and v3 share the left-hand line, with v1's labels outside and v3's inside; v2 and v4 share the right-hand one. Lay a line from v1 to v2, note where it crosses the diagonal, then lay a second line through that point from v3 to v4. Any three of the four values give the fourth. All four transforms must be strictly positive over their domains, and every variable must declare domain.

    The diagonal carries the common ratio and is drawn bare: it is a pivot line, as in any CompoundNomogram, which is what this returns. Following Doerfler (see the Bibliography), the scale factors keep m1/m2 = m3/m4, so the two N charts read the ratio at the same point of the diagonal.

    Example

    julia> nom = proportional_nomogram(
           Variable(:V; domain = (1, 10)),
           Variable(:T; domain = (250, 400)),
           Variable(:nR; domain = (0.01, 0.2)),
           Variable(:p; domain = (0.5, 5)),
       );

julia> s = evaluate(nom; V = 5, T = 300, p = 2);

julia> round(s.nR; digits = 10)
0.0333333333

    Nomograms.ratio_nomogram — Tuple{Variable, Variable, Variable}

    source 
    ratio_nomogram(v1, v2, v3; width = 70, height = 100, title = "")

    An N chart (or Z chart, by its shape) for the ratio relation

    f1(v1) / f2(v2) = f3(v3)

    It has two vertical scales joined by a diagonal, on which the result is read. v3 may leave domain = nothing, in which case the range it can reach is derived from the other two. All three transforms must be strictly positive over their domains.

    Compared with a parallel chart

    multiplicative_nomogram can also chart ratios, by taking logarithms. The N-chart needs no logarithms: the scales stay linear, so precision is even along them and small ratios are not squeezed into a corner. Use it for everyday quantities, such as a rate as distance over time, a concentration or a unit conversion, when the reader will want to interpolate by eye.

    The construction

    Put v1 on x = 0 at y1 = a1 * f1, running up from the bottom-left corner, and v2 on x = W at y2 = H - a2 * f2, running down from the top-right. Take the diagonal between those two corners, D(s) = (sW, sH). A line through a point on each outer scale meets the diagonal where

    s = a1*f1 / (a1*f1 + a2*f2)

    Writing r = f1/f2 and k = a1/a2 that is s = k*r / (k*r + 1), a one-to-one map from the ratio onto the diagonal: reading s back gives r = s / (k * (1 - s)).

    The two scale factors do not have to be equal. The usual textbook derivation makes them equal so that the ratio comes out directly. Here the diagonal's own scale absorbs k instead, so each outer axis can be fitted to the canvas separately. Taking a1 = H/max(f1) and a2 = H/max(f2) anchors the diagonal at the two corners, which gives the layout its N shape.

    The diagonal is drawn only over the part its scale reaches, f1/f2 between min(f1)/max(f2) and max(f1)/min(f2), so it stops short of the corners, which correspond to the ratios 0 and infinity.

    Example

    julia> nom = ratio_nomogram(
           Variable(:distance; domain = (1, 10)),
           Variable(:time; domain = (1, 10)),
           Variable(:speed),
       );

julia> nom[:speed].domain
(0.1, 10.0)

julia> round(evaluate(nom; distance = 6, time = 3).speed; digits = 10)
2.0

    Nomograms.separability_defect — Tuple{Any, Any, Any}

    source 
    separability_defect(F, xdomain, ydomain; n = 9) -> Float64

    Measure how far z = F(x, y) is from being drawable on three straight parallel scales. The result is zero (up to rounding) when transforms f, g, h exist with h(z) = f(x) + g(y). Otherwise it is the largest violation found on an n × n grid.

    This is the classical test: such transforms exist exactly when ln|F_x / F_y| splits into a function of x plus a function of y. A mixed second derivative of that is noisy to compute numerically, so this function checks an equivalent identity that needs only first derivatives:

    L(x, y) − L(x, y₀) − L(x₀, y) + L(x₀, y₀) = 0

    Throws an error if F is not monotone in each variable, because then no straight scale can represent it, whatever the transforms.

    Nomograms.solve_all_on — Tuple{Scale, Tuple{Float64, Float64}, Tuple{Float64, Float64}}

    source 
    solve_all_on(s::Scale, p, q) -> Vector{Float64}

    Every value on scale s whose point lies on the line through p and q, in increasing order. Empty when the line misses the scale.

    A straight line can cross a curved scale more than once, so there is not always a single solution. The usual shortcut, checking only the sign of the residual at the ends of the domain, would report no solution for an even number of crossings and pick one arbitrarily for an odd number. So this function searches the whole domain instead.

    For a straight scale the residual is monotone and this returns at most one value, so charts with only straight scales never have more than one answer.

    Nomograms.svg — Tuple{NomogramDrawing}

    source 
    svg(nom::AbstractNomogram; kwargs...) -> String
svg(d::NomogramDrawing; kwargs...) -> String

    Render a nomogram as a standalone SVG document, returned as a String.

    This backend needs nothing beyond the standard library, so vector output works without any other packages. To put the chart in a Makie Figure, load Makie as well (see nomogramplot).

    Keywords

    • isopleths, style: forwarded to drawing when given a Nomogram.

    • pxperunit = 4.0: pixels per chart unit; the only size control you normally need.

    • padding = 2.0: margin in chart units, added outside the computed bounding box.

    • background = "white", axiscolor, textcolor, isoplethcolors: colours, as any string an SVG renderer accepts. Pass background = "none" for a transparent chart.

    • gridcolor: the colour of a grid's strands and their labels. By default they are drawn like the axes, since they are read like them; pass a lighter colour to make a dense grid less prominent.

    • font: CSS font stack for all text.

    Nomograms.thin_ticks — Tuple{Scale, AbstractVector{<:Real}, AbstractVector{<:Real}, NomogramStyle}

    source 
    thin_ticks(s::Scale, majors, minors, style) -> Vector{TickMark}

    Place as many of the candidate ticks as will fit, rejecting any that would land within min_major_spacing / min_minor_spacing of one already placed.

    Thinning uses distance on the page, not distance in value. This keeps a reciprocal or logarithmic axis readable: the tick values stay round numbers, and where the axis is compressed some of them are dropped.
